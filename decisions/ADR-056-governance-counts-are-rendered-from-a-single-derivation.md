# ADR-056: Governance counts are rendered from a single derivation

**Status:** Accepted
**Date:** 2026-08-12
**Authoring Revision:** be43f54d27675e3041864581342df5767be1cc7e

## Context

`deriveRepositoryCounts` already obtains the ADR total honestly from the
decision registry, and `checkCounts` reports stale prose conservatively. Three
current documents nevertheless copied that total by hand, so every parallel
ADR author inherited an unrelated edit and the integrator repeatedly repaired
the same drift. The decision index is different: its table rows are already a
derived projection and need parity verification, not another template.

The Log4brains practice summarized in
`docs/research/concurrent-integration-frontier-brief.md` §5 is the relevant
discipline: published facts are regenerated from their source rather than
maintained as parallel truths. No Log4brains runtime or general template engine
is needed here.

## Decision

The registry allocation count remains the single ADR-total derivation.
`scripts/render-governance-counts.mjs` rewrites exactly one explicit
`governance:adr_total` marker pair in each of `AGENTS.md`,
`docs/release-readiness.md`, and the implementation-audit skill. It refuses an
unmeasured total, missing markers, and duplicate markers. `--check` is wired
into pre-commit so stale marked prose is rejected before it lands.

The ADR allocator renders and includes those three files atomically with its
registry/index commit. `decisions/README.md` remains structurally generated by
allocation and is tested for exact row parity. Citation migration tests assert
the ID-independent property that only numbers present in the local corpus can
resolve; live cross-namespace example numbers are not test identities.

## Consequences

ADR authors no longer count or edit three prose files. The renderer is
deliberately not extensible: adding a quantity requires an explicit marker and
an honest derivation. In particular, test-case totals remain outside this
static mechanism because `checkCounts` correctly documents that Vitest
execution, not syntax counting, is their source of truth.
