# Changelog

All notable changes to **revoy2** are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Multi-project registry** (ADR-076, Roadmap 23): `arbor project enroll` now records a
  registry entry after a successful, non-preview enrollment — a CLAIM ("this project
  conformed, as of this revision"), never a standing fact. `arbor project registry list`
  and `arbor project registry verify` inspect and recompute discharge on demand;
  `arbor project manage` runs the full gate battery across every registered project in one
  pass. `--new` now initializes the repository it scaffolds rather than requiring one to
  already exist, and `project-conform`'s `--root` flag targets the conformance gate at any
  project, not only the checkout it runs from.
- **`arbor evidence refresh`**: a CLI verb wrapping the existing `evidence.refresh` native
  tool, which was previously reachable only from the MCP tool surface. Mechanizes the three
  evidence-store ordering constraints an operator previously had to carry by hand (graph
  before stores, suite-green before the determinism baseline, commit before verify) and is
  now what `gate:store-freshness`'s remedy text names instead of bare per-store scripts.
- **`arbor doctor` project-governance check**: doctor now reports registry discharge
  (`project_governance` in `--json` output) alongside its existing store-reconciliation and
  harness-integration checks, so a routine readiness check surfaces a drifted or expired
  project registration without a separate `registry verify` call.
- **`@arbor/campaign-support`** (new package): generic campaign support extracted out of
  `@arbor/opencode` so it can be reused outside the OpenCode-specific execution path.
- **`gate:gap-status`** (SUR-06): catches a ROADMAP.md Verified gap register row that
  contradicts the state it claims to describe.
- **`.claude/skills/revoy2-procedure/`**: a situational dispatch skill routing an operator to
  the correct governance mechanism at the moment of need (evidence refresh ordering, file
  moves that break path-keyed stores, ADR authoring vs. acceptance, `REPO_ROOT`-touching
  tests, subagent dispatch, pre-push-only gates, waiver authoring). Its dispatch table and
  CRUD reference appendix are generated by `scripts/generate-procedure-tables.mjs` from
  `scripts/gate-all.mjs`, `cli.ts`, and `native-tool-host.ts`, never hand-typed.
- **`docs/governance-manifest.md`**: one row per governance concern (every `gate:*`, every
  wired Claude hook, and the Tier 2 skill above), naming its scheduling tier, veto authority,
  and evidence — keeping "runs at Stop tier" and "blocks" as the two orthogonal axes they
  actually are.
- **Native reference harness** (`@arbor/harness`, new package): revoy2-owned
  clean-room agent-execution engine — native session engine and worker,
  OpenAI-compatible inference client, model-adapter registry, usage-budget
  controller, context manager, connector registry, and credential broker.
  Depends only on `@arbor/core`.
- **Native execution governance** (`@arbor/mcp`): native agent executor and
  tool host, unified task composer with structured-output task-plan contract,
  harness control plane, durable session journal/execution with restart
  reconciliation, harness readiness checks, native campaign budgets, scoped
  credential leases, critic contract, system-policy approval, worktree machine
  verifier, and declarative subagent execution as an explicit
  `subagent.execute` catalog capability (read-only/no-tools, revision-bound,
  non-recursive).
- **Harness TUI surfaces** (`@arbor/tui`): task-composer, harness-sessions,
  harness-connectors, harness-evaluations, harness-readiness, and
  native-budget screens.
- **Evaluation lanes** (`@arbor/eval`): experimental Agent-UCT scorer with
  deterministic comparison fixture, reuse ledger, staged native-safety CLI,
  and governed agent-search/audit-research lanes.
- **`scripts/lib/waiver-store.mjs`**: the single implementation behind the reachability
  allowlist, branch dispositions, and anti-stub TRIAGE, which previously each reimplemented
  the same rule (an entry carries a reason and a dated expiry; an expired entry blocks) with
  their own schema, validator, and expiry arithmetic. Anti-stub's TRIAGE data moves out of a
  JS array literal inside the gate script into `scripts/anti-stub/triage.json` — it was the
  only governed store that required editing executable source to record a verdict. Also adds
  **`gate:adr-retirement-integrity`**: nothing previously checked that a superseded ADR is
  cross-referenced both ways.
- **`citation_roots`** (ADR-080): a new `arbor.profile.jsonc` key, separate from
  `source_roots`, naming the roots the ADR-citation scan walks. `source_roots` answers "this
  is a package tree" (several gates fail closed without a `tsconfig.tests.json` in every
  subdirectory); `citation_roots` answers the weaker question of where governed code that
  cites decisions lives. Unset means "same as `source_roots`", so every existing profile is
  unaffected. Declaring `citation_roots: ["packages", "scripts"]` for this repo (governance
  code lives under `scripts/`) moved six previously-orphaned records (ADR-033, 034, 048, 059,
  072, 075) into governed status.
- **`adr-trace --trace`**: emits the forward ADR→work map — which commits and files were
  produced under which decision — instead of only the violation set the gate consumed it for.
  `--adr` narrows to one decision; `--since` scopes the window, so `--trace --since <ref>`
  answers "what was worked in this session, and for which decisions."
- **Observation scenario catalog widened from 4 to 10** scenarios (status, `enroll --new`,
  registry list, registry verify, manage, and `repair --apply`, over the project lifecycle),
  closing the gap where nothing exercised the multi-project surface this session built.
  Observations 628 → 799; four of five dormant project-registry symbols are now genuinely
  invoked.
- **Gate roster closed at 37** (`gate:all`, the aggregate, is described only in prose): five
  governance checks that blocked commits and builds from outside the `gate:*` namespace now
  carry `GATE_TIERS` entries. `check` is now derived as `build && test:all && gate:all`, so it
  can never again silently omit a gate — it previously omitted 9 of 31, including
  `project-conform`, `project-registry`, and `gap-status`. Adds `git-write-guard`, a new
  Tier 0 hook.

### Changed

- `gate:store-freshness`'s remedy now names `arbor evidence refresh` first — the only
  mechanism encoding graph-before-stores ordering — with the per-store fallback named second,
  after the gate that detects mis-ordering was found teaching the fix that causes it.

- **Waiver expiry is now enforced across the reachability allowlist**: all 42 entries were
  reconciled to a dated decision (fixed, waived with an ADR/gap reference, or scheduled for
  deletion), and `accepted_tradeoff` anti-stub triage verdicts now carry a shelf life rather
  than standing indefinitely.
- Several gates (`anti-stub`, `lockfile-check`, `tui-catalog-parity`, `typecheck-tests`,
  `vi-refresh`, and others) migrated their repository-root/decisions-dir/allowlist-path
  literals onto the project profile seam, so they run correctly against a project other than
  revoy2 itself.
- The visual-intelligence pipeline is retargetable: source roots are passed explicitly by
  callers rather than hardcoded, making the seam load-bearing for other governed projects.

### Fixed

- Enrollment fixtures no longer register into revoy2's own project registry when the test
  suite spawns the real CLI against a throwaway root (a production-state mutation bug).
- Seven-plus test suites that asserted over broad repository state (content hashes, file
  inventories, a live CLI invocation of `enroll --new`) were isolated from the live checkout
  per ADR-078, after two independent flakes traced to the same cause: a test whose subject
  was "the repository" rather than a fixture, executed inside a checkout other agents were
  concurrently mutating.
- A file move (`@arbor/campaign-support`'s extraction from `@arbor/opencode`) that broke five
  path-keyed stores (ADR proof citations, anti-stub triage entries, determinism seams, docs
  prose, and `tsconfig.tests.json`) was fully repaired, surfacing serially from five separate
  gates before it was caught completely.
- **ADR-079**: `evidence.refresh` refused `determinism:refresh` whenever the suite was red,
  including when the only red test was one the refresh itself could never clear (clearing it
  requires a commit, which this tool deliberately holds no authority to make) — a precondition
  the gated action cannot satisfy deadlocked the operator twice in one session. The
  precondition now filters only the failure set the action can actually clear. Two follow-up
  fixes corrected the first implementation: two proof citations that named a non-existent
  export and the wrong test file, and a failure-set match that compared against vitest's
  duplicate `×`-line rendering (which carries no filename) instead of the `FAIL <file> >
  <test>` line, so the filter had never actually fired.

### Decisions

- **ADR-076**: project registry entries are claims with a required discharge, accepted after
  the registry landed and six obligations were declared against it.
- **ADR-077**: opt-in renderer reachability supersedes ADR-036's O3 unreachability
  obligation, accepted alongside ADR-036's own pointer to its superseding record.
- **ADR-078**: tests that assert over broad repository state must run against a frozen
  snapshot, not the live working tree; tests that drive a real entry point which writes
  durable state must supply their own throwaway persistence directory.
- **ADR-079**: a precondition must be satisfiable by the action it gates.
- **ADR-080**: citation roots are declared separately from source roots.
- 41 additional ADRs accepted this session after their mechanisms were verified built and
  evidenced (ADR-031–037, ADR-062–066, ADR-068–069, ADR-071–073, and 24 more in one pass),
  correcting several that had drifted into stale "not wired" or "gap remains" language.

### Documentation

- **`docs/proposals/procedural-knowledge-hooks-vs-skills.md`**: the four-tier framing for
  procedural knowledge (`PreToolUse` hooks / `Stop`-`pre-push` hooks / skills / gates) this
  batch's tooling implements.
- Seven operator decisions recorded on the manifest-cell-state model, the waiver-format
  unification direction, and the Tier 0 `git-write-guard` addition.
- Reference-harness clean-room specification, OpenRouter native-planner
  bakeoffs (baseline and structured-output rerun), Agent-UCT comparison run,
  and the long-range native-harness security/continuity/deployment roadmap
  (LR-NH-01…07) in `ROADMAP.md`.

## [0.2.0] - 2026-08-01

### Added

- **Core runtime primitives** (`@arbor/core`): supervised task lifecycle with
  leases and reconciliation, idempotent operation registry, sequenced event
  stream with cursor/recovery, bounded output policy with content-addressed
  evidence, model-aware token economy with immutable expansion epochs,
  surveillance detector, typed runtime command/query contracts, and hardened
  tree persistence with interruption/recovery state.
- **Hash-chained ledger evidence** (`@arbor/audit`): gate checkpoints, recovery
  decisions, node communications, interruptions, ledger-witnessed memory
  facts, and telemetry observations — all recorded append-only with SHA-256
  chain links so tamper/truncation/reorder/duplicate/conflict are detected on
  replay, plus a content-addressed raw-output evidence store.
- **Provenance-typed KB** (`@arbor/kb`): SQLite backend behind a config flag,
  exact-replacement projections, sealed v1 JSONL snapshots, and legacy-migration
  handling for unwitnessed rows.
- **Canonical runtime + catalog** (`@arbor/mcp`): single composition root
  (`ArborRuntime`) and `RuntimeCatalogRouter` that MCP stdio, web, and CLI all
  dispatch through; phased interruption, durable governance evidence, ledger-
  derived memory/metrics/telemetry/surveillance projections, durable operation
  + supervisor persistence with restart reconciliation, model-aware token
  epochs, and a structured fault matrix.
- **Backend capabilities** (`@arbor/mcp`): `config.get` (composed effective
  config with source provenance + structural secret redaction), `agent.list`
  (definitions vs live supervisor instances), the `job.*` family + `job.list`
  (bounded queue with dispatch/cancel/retry and pause/resume as a dispatch
  throttle), and `approval.*` + `approval.list` (durable request/approve/reject/
  expire with checks-and-balances forbidding self-approval).
- **OpenCode loop convergence** (`@arbor/opencode`): route the campaign loop
  through canonical runtime ports; interruption sinks, output boundaries,
  recovery leases, and token-economy boundaries replaced parallel orchestration.
- **TUI cockpit** (`@arbor/tui`): headless unidirectional core, deterministic
  shell, input catalog, navigation, bounded Unicode-aware widgets, a canonical
  `RuntimePort` bus, a closed capability-gated screen registry, and ten
  operational screens (campaigns, diagnostics, tasks, operations, output,
  communications, telemetry, config, agents, jobs, approvals).

### Changed

- **Stable communication selection**: `getSelectionCommunications` now filters
  on the communication's logical `as_of` rather than the wall-clock record
  timestamp, making the projection deterministic across replay/restart.

### Fixed

- **Generated provenance field**: corrected runtime event provenance from an
  invalid `model` field to the canonical `generator` field.

### Documentation

- Added ADRs 012–017 (interruption recovery authority, surveillance monitor,
  ledger-witnessed memory, token epochs, recoverable interruption, ledger
  telemetry); updated root and TUI roadmaps; appended the clean-room research
  report; refreshed the successor handoff.
